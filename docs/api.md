# API

REST over HTTPS, JSON, all routes under `/v1`. The OpenAPI spec is generated by `@nestjs/swagger` and served at `/docs` (non-production) and `/docs-json`; the Expo client is generated from it. This page is the outline. The spec, once the API exists, is the source of truth.

## Conventions

- **Auth.** `Authorization: Bearer <Supabase access token>` on every route except `/v1/health`. The Learner is always `token.sub`; no route accepts a learner id from the client.
- **Validation.** Global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })`: unknown fields are rejected.
- **Errors.** `{ "error": { "code": "MISSION_ALREADY_OPEN", "message": "…", "details": {…}? } }`, using standard HTTP statuses (`400` validation, `401`, `404` for missing or not-yours, `409` for state conflicts, `422` for domain rule violations, `429` for throttling).
- **Async work.** Endpoints that start AI work return `202` with a resource to poll.
- **Pagination.** Cursor-based: `?cursor=&limit=` → `{ items, nextCursor }`.
- **Time.** Timestamps are ISO-8601 UTC; local days are `YYYY-MM-DD` in the Learner's time zone.
- **Throttling.** Stricter limits on `POST …/submissions`, `…/drafts` and `…/hints`, since they cost AI money.

## Endpoints

### Profile — FR-01
| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/me` | Profile; creates the Learner row on first call |
| PATCH | `/v1/me` | Level, goal, Senses per Mission, default Mode, time zone, push token |
| DELETE | `/v1/me` | Delete the account and all data ([privacy.md](privacy.md#deletion)) |

### Lexicon & Personal Senses — FR-03, BR-11
| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/senses/:id` | Sense details (meaning, POS, IPA if present, examples, collocations) |
| POST | `/v1/personal-senses/lookup` | `{text}` → matching Lexicon Senses |
| POST | `/v1/personal-senses/drafts` | `{text, context?}` → AI-drafted candidate Senses (`draft`) |
| GET | `/v1/personal-senses` | The Learner's list |
| POST | `/v1/personal-senses` | `{senseId}`: add an existing Sense |
| PATCH | `/v1/personal-senses/:senseId` | Edit a Learner-owned Sense |
| POST | `/v1/personal-senses/:senseId/confirm` | `draft` → `learner_confirmed` |
| DELETE | `/v1/personal-senses/:senseId` | Remove from the list |

### Missions — FR-02, BR-05, BR-08, BR-10
| Method | Path | Purpose |
|---|---|---|
| POST | `/v1/missions` | `{mode?}` → new Mission with Targets; `409` if one is Open |
| GET | `/v1/missions/current` | The Open Mission, or `204` |
| GET | `/v1/missions` | History (FR-11), paginated |
| GET | `/v1/missions/:id` | Mission, Targets with states, and latest verdicts |
| POST | `/v1/missions/:id/hints` | Situation hint questions |
| POST | `/v1/missions/:id/abandon` | Abandon; unfinished Targets become Due |

### Submissions — FR-04, FR-05, FR-06, FR-07, FR-12
| Method | Path | Purpose |
|---|---|---|
| POST | `/v1/missions/:id/uploads` | → `{ path, signedUploadUrl }` for one m4a upload |
| POST | `/v1/missions/:id/submissions` | `{ kind, path? \| text?, journal?, correctionTargetId? }` → `202 { id, status }` |
| GET | `/v1/submissions/:id` | Status, transcript, verdicts with feedback |
| POST | `/v1/submissions/:id/retry` | Re-queue a `failed` Submission |
| GET | `/v1/submissions/:id/audio` | Short-lived signed download URL, while the audio is retained |
| DELETE | `/v1/submissions/:id` | Delete the Submission's content ([privacy.md](privacy.md#deletion)) |
| PUT | `/v1/verdicts/:id/rating` | `{ rating: helpful \| not_helpful \| wrong }` |

### Progress — FR-08, FR-09, FR-10, FR-11
| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/progress` | Status counts, Due count, total XP, current and longest Streak, milestones |
| GET | `/v1/progress/senses` | `?status=&due=` → Senses with status, step and next due date |
| GET | `/v1/progress/senses/:senseId` | One Sense's verdict history |

### Ops
| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/health` | DB + Redis check (unauthenticated; used by Render) |
